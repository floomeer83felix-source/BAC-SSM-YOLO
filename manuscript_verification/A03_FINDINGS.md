# A03 Findings: ablation YAMLs and complexity

## Evidence scope

The public repository at HEAD `66844d4e2c092090e826568d9f4087b44724b953` contains only the complete-model YAML, `yolo26-da-lc-ss2d-scbconv-ca.yaml`. Commit history from the first release (`bcdf87df9dfbe77e28ef310e0c7f04ca6e1cf5d8`) onward does not contain the other requested ablation YAMLs. A separate local legacy experiment directory contains the A0-A8, standard-SS2D, DA-only, LC-only, and gate-ratio YAMLs, but it has no Git repository or commit metadata. Those files are therefore useful as secondary local evidence only and are marked `PARTIAL`, not publicly reproducible evidence.

Every buildable YAML was profiled with the current public code revision, three output classes, image size 640, and `ultralytics.utils.torch_utils.get_flops`. No model was trained. Full results, hashes, module arguments, build failures, and provenance are in `A03_ABLATION_MATRIX.csv` and `a03_profile_details.json`.

## A6 to A8 structural comparison

The preserved local YAMLs differ at P3 layer 16:

```text
A6: C3k2SCBConv, [256, True]
A8: C3k2SCBNeckCAPlus, [256, True]
```

Backbone DA-LC blocks, P4 fusion, P5 fusion, channels, repeat counts, and expansion arguments otherwise remain the same between these two YAMLs. `C3k2SCBNeckCAPlus` is a composite block with a different internal parameterization; it is not an independent CA layer appended after the A6 block. A parameter decrease is therefore structurally possible through replacement. Under the current public code, the replacement changes 5.352000M / 15.438706G to 5.342903M / 15.313958G. This explains the direction of the decrease, but not the full paper difference of 5.42M / 15.76G to 5.34M / 15.28G, which depends on an unversioned legacy implementation/profile.

## Factorial interpretation

A0 is the control. A4 and A5 are clean comparisons against A0 for replacing the context family with standard SS2D or DA-LC-SS2D. A5 to A6 can be treated as addition of the declared multi-site BAC neck configuration, but BAC placement differs from A1, where SCBConv is used in the backbone. A2 is not a bare CA insertion: it replaces the P3 fusion with the composite `C3k2SCBNeckCAPlus`, which also includes local/depthwise/asymmetric/factorized branches, spatial gating, ECA, refinement, and a shortcut. A3 inherits the same problem. A6 to A8 is a composite block replacement, not a strict additive BAC-then-CA step. Therefore, Table 4 is not a fully orthogonal three-factor design even though several pairwise comparisons remain informative.

Table 5 is structurally controlled in the preserved local YAMLs because standard SS2D and DA-LC-SS2D are swapped while the same BAC/CAPlus neck is retained. Only the DA-LC row is publicly released, so public traceability of the table as a pair is `PARTIAL`.

## Table 6 and Table 8

The local machine contains DA-only and LC-only YAMLs, but neither their classes nor their YAMLs are present in the public repository. They fail to build under the public code revision. Accordingly, DA-only and LC-only are **NOT REPRODUCIBLE FROM PUBLIC REPOSITORY** and should not be presented as publicly reproducible experiments.

The public `SS2DDALC` constructor has an internal `dir_hidden_ratio=0.0625` default, but `VSSBlockDALC`, `C3k2DALCSS2D`, and `C2PSADALCSS2D` do not expose or forward this value through the public YAML interface. The public code also lacks the `R1` and `R3` wrapper classes named by the local ratio YAMLs. Ratios 0.03125 and 0.125 are therefore **NOT TRACEABLE FROM PUBLIC RELEASE**. The 0.0625 default is code-confirmed, but the public YAML cannot vary it.

## Required answers

1. The A6 to A8 decrease can be explained qualitatively by P3 block replacement, but the paper's exact decrease is not reproduced by current public code.
2. A8 should not be described as simply “A6 + CA.” It should be described as replacing the P3 BAC fusion block with the composite CAPlus refinement block while retaining the other A6 stages.
3. The defensible single-factor comparisons are A0 to A4, A0 to A5, A5 to A6 as a declared BAC-neck intervention, and the standard-versus-DA-LC pair in Table 5. A2/A3 and A6-to-A8 are not strict bare-CA/additive comparisons.
4. Table 5 is only partially traceable: both local YAMLs exist and build, but only the DA-LC complete row is in public Git history.
5. DA-only and LC-only have no public configuration or class evidence. They are not publicly reproducible.
6. Ratios 0.03125 and 0.125 have no public configuration/class evidence. Only the hard-wired 0.0625 default is visible in the release.
7. Table 4 needs corrected labels/footnotes explaining BAC placement and composite CAPlus replacement; Table 5 needs a provenance qualifier; Table 6 and Table 8 require public artifacts or must be downgraded/removed.
8. A6, A7, the standard Table 5 row, and all retained Table 6/8 variants need complexity values regenerated from the exact code revision that produced their checkpoints. Reprofiling against current public code cannot retroactively establish old values.
9. If the exact original code/YAML provenance cannot be recovered, Table 6 and Table 8 should be removed from the main evidentiary chain or explicitly labeled exploratory. The complete A8 model remains reproducible.
